# 광주대구선 CCTV + 도로기상(RWIS) 통합 대시보드

무안광주대구선(12호선) **함양IC(95.0km) ~ 옥포JC(176.0km)** 구간의
**CCTV 123대 / 62개 지점** 목록과, 기상청 도로기상정보시스템(RWIS)의
**도로살얼음(FSM)·도로가시거리(VIR) 위험등급**을 한 화면에서 보는 통합본입니다.

| 파일 | 역할 |
| --- | --- |
| `worker.js` | Cloudflare Worker(ES Module). CCTV 목록·마스터 매칭, RWIS 16개 구간 등급, CCTV 스트림 주소를 JSON으로 중계 |
| `index.html` | 단일 파일 반응형 대시보드. Worker 미연결/오프라인에서도 62지점 구조를 그립니다 |
| `data/cctv_master.json` | 123대/62지점 마스터(이정·시설·주소·좌표·CCTV ID·RWIS 구간) |
| `data/route_geo.json` | 노선도 배경용 시도·시군 경계(SVG 좌표로 투영·단순화) |
| `data/rwis_latest.json` | `tools/rwis_export.py` 로 만든 RWIS 사전 계산 스냅샷(예시) |
| `tools/build.py` | CSV → 마스터 JSON → `worker.js`·`index.html` 데이터 주입 |
| `tools/build_geo.py` | `data/geo` 경계 원본 → `data/route_geo.json`(노선도 배경) |
| `tools/rwis_export.py` | RWIS 16개 구간 등급을 미리 계산해 작은 JSON 생성(무료 플랜 CPU 대응). 최신 5분 슬롯이 비면 직전 슬롯으로 후퇴 |
| `tests/` | worker 54건 + 대시보드 223건 + 화면 62건 자동 검증(실데이터·5분 폴백·세로/가로 노스크롤 레이아웃·v6 다크 지도/리포트/자동 갱신/상향 하이라이트·v8 방향 일치/라벨 여백·v9 셰브런 대칭/등록 CCTV/버튼감·v10 좁은 세로 카드 잘림/스크롤 제거·v11 카드 여백/배지 `… 전`/화살표 분리 포함) |
| `deploy/rwis-export.yml` | GitHub Actions 로 5분마다 RWIS JSON → GitHub Pages |
| `wrangler.toml`, `.dev.vars.example` | 배포 설정 예시 |

> 영상 트래픽은 Worker를 지나가지 않습니다. Worker는 **목록/주소(JSON)만** 중계하고,
> `.m3u8`·영상 조각은 브라우저의 `hls.js`가 로드플러스 CDN(`*.hscdn.com`)에서 직접 받습니다.

## 1. 데이터

- **CCTV 123대 = 62지점** (대구방향 61 · 광주방향 62). 61개 지점은 양방향, `두산` 1곳만 광주방향 단방향.
- 원본: `misc-db/gwangju-daegu-cctv/gwangju_daegu_cctv_hamyang_okpo.csv` (2026-11-20 조사)
  — 한국도로공사 로드플러스 CCTV 목록 + 길통아 API 공식 이정 + Kakao 역지오코딩 + OSM 노선 투영.
- CCTV ID는 **지점당 1개**(`cctv00005751` 등). 로드플러스도 같은 지점의 양방향을 같은 ID·같은 영상으로 제공하므로,
  팝업의 영상은 지점 기준 1개이고 **이전/다음 지점** 버튼으로 이동합니다.
- 이정이 `산출`인 지점 35곳은 좌표를 노선에 투영한 값(오차 ±0.3~0.5km)입니다.

### RWIS 구간 경계

Worker는 8개 IC~IC 구간 × 2방향 = **16개 존**을 사용합니다(`conzoneId` = `0120CZ` + 방향 + 일련번호).

| 구간 | 이정(km) | 무안→대구 | 대구→무안 |
| --- | --- | --- | --- |
| 함양IC–함양JC | 95.00–97.30 | `0120CZE160` | `0120CZS160` |
| 함양JC–거창IC | 97.30–121.10 | `0120CZE170` | `0120CZS170` |
| 거창IC–가조IC | 121.10–131.10 | `0120CZE180` | `0120CZS180` |
| 가조IC–해인사IC | 131.10–146.40 | `0120CZE190` | `0120CZS190` |
| 해인사IC–고령IC | 146.40–152.90 | `0120CZE200` | `0120CZS200` |
| 고령IC–동고령IC | 152.90–165.52 | `0120CZE210` | `0120CZS210` |
| 동고령IC–고령JC | 165.52–166.99 | `0120CZE220` | `0120CZS220` |
| 고령JC–옥포JC | 166.99–176.00 | `0120CZE230` | `0120CZS230` |

- `E` = RWIS 방향코드 `cdpntTmnlDirDvCd='E'`(종점 방향) = **무안 → 대구** = 대시보드의 `대구방향`
- `S` = `'S'`(기점 방향) = **대구 → 무안** = `광주방향`
- 지점 카드의 등급은 **그 지점이 속한 구간**의 등급입니다. 경계(IC)에 걸친 지점은 그 IC에서 시작하는 구간으로 묶습니다
  (예: 121.10km `거창` → 거창IC–가조IC).

## 2. API

| 엔드포인트 | 캐시 | 내용 |
| --- | --- | --- |
| `GET /api/status` | 각각 | CCTV + RWIS 통합(권장). 한쪽이 실패해도 다른 쪽은 살아남고 `errors`에 담깁니다 |
| `GET /api/cctv` | 15분 | ITS Open API 목록 + 123대 마스터 매칭(`points`) + ITS 미매칭 이름 |
| `GET /api/rwis` | 5분 | 16개 구간 FSM/VIR 등급·링크 분포·관측시각(`tm`)·경보 목록 |
| `GET /api/stream?cctvId=cctv00005751` | 2분 | 로드플러스 실시간 HLS 주소 + 스냅샷 + 이전/다음 지점 |
| `GET /` | — | 사용 안내(설정된 시크릿 여부 포함) |

모든 응답에 `Access-Control-Allow-Origin: *` 가 붙습니다. `?refresh=1` 로 캐시를 건너뜁니다.

```jsonc
// GET /api/rwis (요약)
{
  "ok": true, "kind": "rwis",
  "tm": { "FR": "202611210030", "VR": "202611210015" },
  "tmLabel": { "FR": "2026-11-21 00:30", "VR": "2026-11-21 00:15" },
  "tmLatest": { "FR": "202611210035", "VR": "202611210015" },
  "tmFallbackSteps": { "FR": 1, "VR": 0 },
  "tmFallback": { "FR": true, "VR": false, "note": "최신 기준시각 표가 아직 없어 5분 단위로 직전 슬롯을 씁니다." },
  "summary": { "fsmMax": 3, "virMax": 0, "fsmZoneCounts": [12,0,0,4], "virZoneCounts": [16,0,0,0] },
  "alerts": [ { "id": "0120CZE170", "name": "함양JC-거창IC", "dirLabel": "대구방향", "fsm": 3, "vir": 0 } ],
  "zones": [
    {
      "id": "0120CZE170", "name": "함양JC-거창IC", "dir": "E", "dirLabel": "대구방향",
      "startKm": 97.3, "endKm": 121.1, "lengthM": 24170, "linkCount": 34,
      "fsm": { "level": 3, "levelName": "위험", "levelDetail": "3단계 · 위험",
               "counts": [0,0,0,34], "knownLinks": 34, "totalLinks": 34 },
      "vir": { "level": 0, "levelName": "안전", "counts": [34,0,0,0], "knownLinks": 34, "totalLinks": 34 }
    }
  ]
}
```

`counts`는 `[0단계, 1단계, 2단계, 3단계]` 링크 수입니다. 등급은 기상청 RWIS 공식 표기 그대로 **`0 안전 · 1 관심 · 2 주의 · 3 위험`** 입니다(v6에서 `경계` 표기를 바로잡았습니다).

### 등급 계산 규칙 (RWIS 웹사이트와 동일)

1. `getConZoneByRoadNo.do` 로 구간별 `LINK_ID` 목록을 받고 (POST, `roadNo=012 / roadNoN1=12 / roadNoN2=0120`)
2. `getNrmRoadRiskTimeSet?riskCd=FR|VR` 로 최신 기준시각 `nrmMaxTm` 을 받고
3. `getNrmRiskRoadTableAll?riskCd=…&tm=…` 로 전체 링크 표를 받아 **우리 구간 링크만 추린 뒤**
   링크별 `FSM`/`VIR` 값 중 **최댓값**을 그 구간의 등급으로 씁니다.
   `null`·빈 값·0~3 밖의 값은 결측으로 보고 제외합니다.
4. **5분 슬롯 폴백** — 기준시각(`nrmMaxTm`)보다 표가 몇 분 늦게 올라오면 그 슬롯 조회는
   HTTP 200 + `resultCode 03 NODATA_ERROR` + 빈 `items` 로 돌아옵니다. 이때 실패로 끝내지 않고
   **5분씩 최대 4단계(20분 전)까지 거슬러 올라가** 실제 값이 있는 표를 씁니다.
   응답의 `tm`·`tmLabel` 은 **실제로 등급을 읽은 관측시각**이고, 최신 기준시각은 `tmLatest`,
   후퇴 단계는 `tmFallbackSteps` 에 따로 남습니다. 5개 슬롯이 모두 비면 `502 RWIS_EMPTY_TABLE`
   (`tools/rwis_export.py` 는 `RuntimeError`)로, 시도한 5개 슬롯과 `resultCode` 를 함께 알려 줍니다.

## 3. 배포

### 3-1. Cloudflare Worker

```bash
npm install -g wrangler
wrangler login

wrangler secret put ITS_API_KEY        # https://www.its.go.kr/opendata 에서 발급
# (권장·무료 플랜) wrangler secret put RWIS_SOURCE_URL   ← 4장 참고
wrangler deploy
# → https://gwangju-daegu-cctv.<내서브도메인>.workers.dev
```

로컬 확인:

```bash
cp .dev.vars.example .dev.vars    # 키 채우기 (.dev.vars 는 커밋 금지)
wrangler dev
curl -s "http://127.0.0.1:8787/api/rwis" | head -40
```

### 3-2. 대시보드 올리기

`index.html` 은 파일 하나로 동작합니다. 세 가지 중 편한 방법을 쓰세요.

1. **파일로 열기** — `index.html` 더블클릭. Worker 주소를 넣고 `연결`.
   (`file://` 은 `localStorage` 가 막힐 수 있어 주소가 저장되지 않을 수 있습니다.)
2. **정적 호스팅** — GitHub Pages·Cloudflare Pages·NAS 웹폴더에 `index.html` 만 올립니다.
   같은 도메인에 Worker를 붙였다면 주소 칸에 `/api` 없이 워커 루트만 넣어도 됩니다.
3. **Worker가 함께 서비스** — `index.html` 을 `public/` 에 두고 `wrangler.toml` 의 `[assets]` 주석을 풀면
   Worker 주소 하나로 화면과 API가 같이 나옵니다.

> 이전에 만든 19지점 팝업 대시보드(`downloads/cctv_popup_dashboard.html`)도 그대로 쓸 수 있습니다.
> `/api/cctv` 가 예전과 같은 `cctvs` 배열과 `stats.unmatchedLabels` 를 계속 내려줍니다.
> 다만 19지점 목록은 그 HTML 안에 들어 있으므로, 123대 전체를 보려면 이번 `index.html` 을 쓰세요.

## 4. 무료 플랜 CPU와 `RWIS_SOURCE_URL` (중요)

RWIS 위험표는 **한 번에 약 2.8MB(2만 8천 링크)** 입니다. FR·VR 두 장을 받아 파싱하면
Worker CPU를 대략 **30~40ms** 씁니다. Cloudflare Workers **무료 플랜 CPU 한도는 요청당 10ms**라
5분마다 캐시가 비는 순간 요청이 `1102`(CPU 초과)로 실패할 수 있습니다.
(유료 플랜은 30초라 문제 없습니다.)

그래서 **5분마다 미리 계산해 두고 Worker는 작은 JSON만 읽는 방식**을 함께 넣었습니다.

```bash
# 아무 곳(NAS·PC·Actions)에서 5분마다 실행
python3 tools/rwis_export.py --out public/rwis.json    # 약 12KB
```

1. `deploy/rwis-export.yml` 을 저장소 `.github/workflows/` 로 복사
2. 저장소 Settings → Pages → Source = **GitHub Actions**
3. 한 번 수동 실행해 `https://<아이디>.github.io/<저장소>/rwis.json` 확인
4. `wrangler secret put RWIS_SOURCE_URL` 에 그 주소 입력 → 재배포

이 모드에서 Worker는 3단계 API를 직접 부르지 않고(`/` 안내의 `env.rwisMode` 가 `source-url`),
받은 JSON을 그대로 중계합니다. 형식이 어긋나면 `502 RWIS_SOURCE_BAD_SHAPE` 로 알려 줍니다.
NAS·R2·S3 어디에 두어도 됩니다.

`RWIS_SOURCE_URL` 을 비우면 기존처럼 직접 호출 모드로 동작합니다(유료 플랜·소규모 테스트용).

## 5. 대시보드 사용

화면은 **스크롤이 없는 원스크린**입니다. `body` 가 `100dvh` 로 고정되고, 넘치는 내용은
각 패널 **안에서만** 스크롤합니다(목록 패널). 상단 바는 한 줄로 줄이고, Worker 주소 입력은
**⚙ 설정 팝오버**로 접었습니다(자동으로 열지 않고 ⚙ 버튼이나 **상태 배지**를 눌렀을 때만 열립니다).

### 5-0. 레이아웃

| 화면 | 구성 |
| --- | --- |
| 데스크톱 (≥1024px) | 좌(~63%) **노선도 캔버스 + 1줄 컨트롤 + 구간 밴드**, 우(~37%) **경보 요약 · 지점·CCTV 목록** 2단. 목록은 패널 안에서만 스크롤 |
| 모바일 세로 (<1024px) | 상단 44px 헤더(상태 배지·⚙·새로고침) + **노선 카드** + **하단 엄지 존**. 노선 카드는 위에서부터 `[살얼음/가시거리 · 대구/광주/양방향]` → 관측 한 줄 → **서→동 가로 노선도** → **8구간 타일 2×4**(구간명·이정·양방향 등급·지점/CCTV 수, 누르면 바텀시트) 순서로 화면을 꽉 채웁니다 |
| 모바일 가로 (회전, 높이 ≤560px) | **몰입형**: 헤더와 엄지 존을 접고 노선도가 화면 전체를 씁니다. 조작은 오른쪽 **68px 엄지 레일**(❄살얼음 / 👁가시 · ↑대구 / ↓광주 / ⇅양방향 · 📹CCTV / 📸저장 / ⟳**갱신** / ⚙설정)로 옮겨 노선도를 가리지 않으며, 노치·제스처 바는 `env(safe-area-inset-*)` 로 피합니다. CCTV 목록은 2열 컴팩트 리스트 |

1. **연결** — ⚙(또는 상태 배지)를 눌러 Worker 주소를 넣고 `연결` (`localStorage` 에 저장). 실패해도 샘플 모드로 62지점·123대가 그대로 그려집니다.
   같은 ⚙ 안에서 **자동 새로고침 주기**(수동 / 1분 / 5분 / 10분 / 30분 / 1시간, `localStorage`)와 **한 장 요약 리포트 PNG**, **자료 기준(이정·등급)** 을 함께 봅니다.
   자동 갱신을 켜면 상단에 `다음 갱신 04:59` 카운트다운이 표시되고, 팝업·캡처 화면·백그라운드 탭에서는 건너뜁니다.
2. **도로기상(RWIS) 위험**
   - 요약 3칸: 살얼음 최고 등급, 가시거리 최고 등급, 관측시각·구간 수
   - 필터 `전체 16` / `살얼음 주의 이상 N` — 2단계(주의) 이상 구간만 남깁니다
   - **구간 밴드**(노선도 아래 8칸): 구간을 누르면 그 구간만 목록에 남고, 2단계 이상은 붉은 테두리.
     모바일은 목록 화면 위의 가로 스크롤 칩으로 같은 필터를 씁니다
   - 뱃지에 마우스를 올리면 구간 내 링크 분포(위험 n · 주의 n · 관심 n · 안전 n)가 보입니다
3. **지점 · CCTV**
   - 검색: 지점명·주소·CCTV ID·시설·비고를 한 번에 찾습니다
   - 시설 필터: `전체 / IC·JC / 휴게소·졸음 / 터널·교량 / 일반(마을)`
   - 방향 탭: `전체 / 광주 / 대구` — 고른 방향 재생 버튼만 남습니다
   - `이정 ▲/▼` 로 오름·내림차순 전환
   - 카드의 `❄` `👁` 뱃지는 그 지점이 속한 구간의 양방향 중 **높은 등급**이고, 툴팁에 방향별 등급이 나옵니다.
     카드를 누르면 바로 영상이 열립니다(방향 버튼으로 방향 지정)

### 5-0-8. v10에서 달라진 점 — 좁은 모바일 세로 카드 잘림·스크롤 제거 (2026-11-23)

성보 님이 삼성 브라우저에서 라이브 화면을 직접 찍어 보내 준 증상(주소창·하단 바 때문에 가용 높이가 660~720px로 줄면
8구간 카드의 아래 줄과 `📹 인근 CCTV ›` 가 **세로로 반쯤 잘리고** 오른쪽 스크롤바가 생김)을 고쳤습니다.

- **원인** — 모바일 구간 밴드가 `grid-auto-rows: minmax(0, 1fr)` 로 **행 높이를 남는 공간에 맞춰 강제로 눌렀고**,
  카드는 `overflow` 로 넘치는 부분을 감췄습니다. 그래서 행이 52px까지 줄면 제목(13)+등급(17)+이정/버튼(17)=47+패딩이 들어가지 못해
  버튼이 반토막 났습니다. 스크롤바는 밴드 자체의 `overflow-y: auto` 였습니다.
- **행은 내용 높이만큼** — `grid-auto-rows: minmax(min-content, 1fr)` 로 **내용보다 작아지지 않게** 바닥을 잡았습니다.
  넘치는 만큼은 카드가 아니라 **지도가 먼저 줄어듭니다**(`flex: 1 1 auto; min-height: 104px`).
- **카드는 3줄 컴팩트** — 제목(11px 안팎) / `● 양방향 위험` / `이정 + 📹 인근 CCTV ›` 를 한 줄씩, 패딩·줄간격·폰트를
  `clamp(…dvh…)` 로 화면 높이에 비례해 줄입니다. 대구·광주 등급이 다를 때는 `대구 주의 · 광주 안전` 처럼 **한 줄**,
  다른 지표 경고(`● 가시거리 주의`)는 같은 줄 오른쪽에 붙여 8개 카드 높이를 모두 같게 유지합니다.
- **관측 한 줄 정리** — 좁은 화면에서는 출처를 `스냅샷 12:45 · 11시간 전` 으로 짧게 쓰고 **0건 단계는 숨깁니다**
  (`위험 1 · 안전 7`). 구분점은 항목에 붙여 숨긴 항목이 `·` 자국을 남기지 않고, 한 줄에 다 들어갑니다(데스크톱은 그대로 전부 표시).
- **스크롤 제거** — 페이지(`100dvh`)와 구간 밴드 모두 **안쪽 스크롤 없음**. 카드 하단이 하단 독을 침범하지 않습니다.
- **지도 비율 유지** — 지도는 `calc((100vw - 34px) / 1.72)` 로 높이를 묶어 세로에서도 **서→동 가로**(비율 1.7:1 이상)를 지키고,
  `ResizeObserver` 로 카드 높이가 몇 px 달라져도 캔버스가 상자 비율을 다시 따라갑니다.
- **좁은 폭 헤더** — 400px 이하에서 제목이 `광주대…` 로 잘리지 않게, 자동 갱신이 꺼져 있을 때 `수동 갱신` 칩을 접습니다(⚙에서 확인).
- **높은 화면** — 780px 이상에서는 남는 높이를 카드 글자·손가락 여백으로 씁니다(제목 12px, 버튼 18px).
- **검증** — `tests/test_dashboard_visual.py` 에 **[V3] v10 20건**을 더했습니다. 390×680·360×640·390×700·360×600 네 화면에서
  `scrollHeight ≤ innerHeight`, 구간 밴드 안쪽 스크롤 0, **8개 카드의 제목·등급·이정·`인근 CCTV` 버튼 bounding box가

### 5-1. 노선도 (인포그래픽)

왼쪽 카드가 **함양IC(95.0km) → 옥포JC(176.0km) 노선도**입니다. `cctv_master.json` 의 62지점 실좌표를
등장방형(equirectangular) 투영해 그린 SVG 이고, 배경에는 시도 4개(경남·경북·전북·대구)와 시군 13개 경계를
깔았습니다(공개 경계 단순화, `tools/build_geo.py`). 서버·CDN 없이 파일 하나로 그려집니다.

- **캔버스 네 가지** — 화면은 다크 테마 `1600×900`(가로), 휴대폰은 상자 비율에 맞춘 캔버스, **공유 리포트는 라이트 테마 `1600×900` 지도**를 리포트 안에 합성합니다.
  휴대폰은 화면이 차지한 상자 크기를 읽어 **그 비율 그대로 캔버스를 다시 잡습니다**(2배 해상도로 그려 선명하게).
  어느 화면에서도 **회전 없이 정북 기준**이라 노선은 늘 **서→동(함양IC 왼쪽 → 옥포JC 오른쪽)** 으로 흐르고,
  라벨은 겹침·도로 가림·지도 밖을 비용으로 두는 자동 배치기가 고르며, 지도 밖으로 나가는 라벨은 안쪽으로 당겨 잘리지 않습니다.
- **구간별 색** — 8개 RWIS 구간을 0 안전(파랑)·1 관심(노랑)·2 주의(주황)·3 위험(빨강, 굵게+글로우)
  으로 칠하고 흰 케이싱·그림자로 도로처럼 띄웠습니다. 진행 방향은 흰 화살표(셰브론), 등급이 없으면 회색 점선(값을 지어내지 않음).
- **라벨 자동 배치** — 13개 IC·JC·터널 이름은 겹침·도로 가림·지도 밖을 비용으로 두고 자리를 고르는
  간단한 배치기로 필(pill) 카드 + 지시선을 붙입니다. `가야1TN`·`가야3TN`처럼 붙어 있는 노드도 겹치지 않습니다.
- **분기선 · 거리 눈금** — 함양JC(통영대전선), 고령JC·옥포JC(중부내륙선·지선)는 초록 분기선으로 구분하고,
  10km 눈금(100~170)을 노선에 표시합니다(라벨과 겹치면 생략).
- **방향 전환** — `양방향`(기본, 상·하행 이중선) / `대구 ↑` / `광주 ↓`. 단방향을 고르면 카드·요약·목록도 그 방향 등급만 씁니다.
- **위험 종류** — `❄ 살얼음(FSM)` / `👁 가시거리(VIR)` 전환 시 제목·관측시각·등급이 함께 바뀝니다.
- **연동** — 데스크톱에서 구간을 누르면 그 구간 지점만 목록에 남고, IC·터널 이름을 누르면 그 지점 CCTV 모달이 열립니다.
  휴대폰에서는 구간(노선 위든 아래 8구간 타일이든)을 누르면 **바텀시트**로 그 구간의 양방향 등급·CCTV 수를 보여 주고, `이 구간 CCTV 보기` 로 목록 탭으로 넘어갑니다.
- **휴대폰 세로** — 가로 노선도를 그대로 유지하고, 지도 아래 남는 공간을 **8구간 타일(2×4)** 로 채워 스크롤 없이 씁니다.
  더 크게 보려면 폰을 **가로로 돌리면** 헤더·독이 접히는 몰입형(오른쪽 사이드 레일)으로 바뀌고, 브라우저 기본 **두 손가락 확대**도 그대로 됩니다.
- **공유 리포트(PNG)** — 화면이 세로형이어도 저장은 언제나 라이트 테마 지도를 다시 그려
  **상단 요약 + 노선도 + 8구간 등급표**를 한 장(`3200×4140`)으로 만듭니다. 출처·이정 기준·등급 정의까지 담기고,
  SVG → `Image` → `canvas` 합성 → `canvas.toBlob` 만 쓰므로 CDN·서버 없이 오프라인에서도 동작합니다
  (`gwangju-daegu-report-ice-YYYYMMDD-HHMM.png`).
- **캡처 모드** — 상단바·목록을 감추고 노선도만 화면 가득 크게 보여 줍니다(`Esc` 또는 `✕`로 종료).

  `<link rel="manifest" href="manifest.webmanifest">` 한 줄. `display: standalone`, `theme_color: #0a101c` 면 충분합니다.
  아이콘은 192/512px 두 장.
- **서비스 워커**는 `index.html`(과 앱 셸)만 캐시하고 **`/api/*` 는 네트워크 우선**으로 두세요.
  등급은 5분마다 바뀌므로 캐시하면 오래된 위험등급을 보여 주게 됩니다.
- **Web2APK**(WebView 포장): `index.html` 을 앱 asset에 넣고 Worker 주소를 앱 설정값으로 미리 채우면
  주소 입력 없이 바로 뜨고, 상단 상태 배지(●)나 ⚙ 를 누르면 주소 입력칸이 열립니다. `localStorage` 가 살아 있으니 한 번 넣으면 다음부터는 자동 연결됩니다.
- **APK 오프라인**: 화면을 앱에 넣을 때 `hls.js` CDN이 막히는 환경이면 `hls.min.js` 를 앱 asset에 같이 넣고
  `<script src="hls.min.js">` 로 바꾸세요. 영상 자체는 어차피 네트워크가 필요합니다.
- **혼합 콘텐츠**: ITS가 `http://` 스트림을 줄 때 https 화면에서는 브라우저가 막습니다.
  이번 구성은 로드플러스 `https://…hscdn.com` HLS만 쓰므로 해당 없음. 단, WebView에서 `mixedContentMode` 는
  `never-allow` 로 두는 편이 안전합니다.
- **자동재생**: 모바일 브라우저는 소리 있는 자동재생을 막습니다. 플레이어는 `muted`+`playsinline` 으로 열리고,
  사용자가 소리를 켜는 방식입니다.
- **가로 화면**: 영상 팝업은 16:9(모바일 4:3)로 고정됩니다. 본 화면은 가로로 돌리면 몰입형 노선도로 자동 전환되므로,
  WebView/APK 에서는 `screenOrientation` 을 `fullUser`(또는 `unspecified`)로 두면 그대로 동작합니다.

## 9. 문제 해결

| 증상 | 원인 / 조치 |
| --- | --- |
| `ITS_API_KEY_MISSING` (500) | `wrangler secret put ITS_API_KEY` 후 재배포 |
| `UPSTREAM_UNREACHABLE` / `UPSTREAM_TIMEOUT` (CCTV) | `openapi.its.go.kr:9443` 차단 가능성 → NAS·Actions로 JSON을 받아 `CCTV_SOURCE_URL` 지정 |
| `RWIS_NO_TM` (502) | 기준시각(`nrmMaxTm`) 자체를 못 받음. 잠시 뒤 `?refresh=1`. 반복되면 `RWIS_BASE`·기상청 점검 확인 |
| `RWIS_EMPTY_TABLE` (502) | 최신 + 직전 4개(20분) 슬롯이 **모두** 비었을 때만 남습니다. `detail.tried` 의 `resultCode` 확인 — `03`이면 기상청 표 생성 지연이 20분을 넘긴 것 |
| `RWIS_NO_CONZONE` (502) | `roadNo` 파라미터 또는 노선 코드 변경. `/api/rwis` 응답의 `detail` 확인 |
| `RWIS_SOURCE_BAD_SHAPE` (502) | `RWIS_SOURCE_URL` JSON이 `tools/rwis_export.py` 출력 형식인지 확인 |
| 5분마다 한 번씩 1102/타임아웃 | 무료 플랜 CPU 한도 → **4장**의 `RWIS_SOURCE_URL` 방식으로 전환 |
| 지도/목록은 뜨는데 등급이 `—` | Worker는 붙었지만 RWIS만 실패. 상태줄의 `RWIS 오류: …` 확인 |
| 영상 주소를 받지 못함 | 로드플러스 API 일시 오류. `다시 시도`. 계속되면 로드플러스 CCTV검색에서 직접 확인 |
| 영상이 안 나옴 | 스트림 서버 장애 또는 브라우저 코덱. Chrome 최신·Safari는 네이티브 HLS로 재생 |
| ITS CCTV 0건 | 키 미설정이거나 좌표 범위 밖. 이때도 마스터 62지점 목록은 정상 표시 |
