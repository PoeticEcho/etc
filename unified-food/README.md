# 🍱 unified-food — 벨루가 + 유튜브 맛집도감 통합 맛집 DB

벨루가 테마지도(`velooga.com/map`) 맛집 DB와 유튜브 맛집도감(`food.lovizu.com`) 전수 DB를 **하나의 SQLite DB로 통합**하고, 좌표가 없던 맛집을 모두 지오코딩해 채운 데이터 세트입니다. 두 소스는 `restaurants.source` 컬럼(`velooga` / `lovizu`)으로 구분하며, 원본 행·ID·분류는 그대로 보존했습니다.

## 통합 방식

1. **한 테이블에 소스 구분 컬럼** — `restaurants`(맛집), `places`(전체 장소), `themes`(테마) 모두 원본 컬럼 순서 뒤에 `source`를 붙였습니다. 원본 ID(`mt-…` 벨루가, `lv-0001`~`lv-1943` 맛집도감)는 겹치지 않아 그대로 씁니다.
2. **러비즈 추가 정보 보존** — 맛집도감만 가진 카카오·네이버 평점/리뷰수, 플레이스 링크, 영업시간, 휴무, 주차, 웨이팅, 좌석, 예약, 대표 메뉴·가격, 본문 정보 표(`info_rows`)는 `restaurants_extra`(1:1, 1,943행)와 JSON의 `extra`에 손실 없이 담았습니다.
3. **테마 정리** — 같은 프로그램이 두 소스에서 다른 ID로 들어온 경우가 있어 `themes.theme_group`(프로그램 이름)으로 묶었습니다: 성시경 먹을텐데(`meogeultende` 1행으로 병합, 283곳), 더들리(`dudley` 136 + `dudely` 81 = 217곳), 비밀이야(`bimiliya` 155 + `bimirya` 51 = 206곳). 나머지 34개 테마는 원본 그대로입니다.
4. **중복 처리** — 상호 정규화(공백·괄호·문장부호 제거)와 도로명주소(도로명+건물번호)가 모두 같은 행을 한 그룹으로 묶어 `dup_group`(`D0001`…)·`dup_count`를 부여했습니다. **행은 삭제하지 않았습니다** — 두 소스의 설명·테마·평점이 서로 달라 각각 남기는 편이 정보 손실이 없기 때문입니다. 하나로 본 목록이 필요하면 `v_unified_dedup` 뷰(3,434곳)를 쓰세요.
   - 중복 189그룹 = 두 소스가 같은 가게를 소개한 교차 중복 163그룹 + 벨루가 한 소스 안에서 여러 테마에 중복 등재된 26그룹(예: 같은 가게가 `meogeultende`·`hongdae` 두 테마에 각각 등록).
   - 그룹 크기: 2행 그룹 173개(346행) · 3행 그룹 13개(39행) · 4행 그룹 3개(12행).
5. **좌표** — 아래 「좌표 보강」 참고. 모든 행에 `latitude`/`longitude`가 있고, 값의 성격은 `geo_provider`·`geo_precision`으로 구분합니다.

- 벨루가 DB 원본에 좌표가 있던 297건 가운데 41건은 전수 지오코딩 캐시 값과 100m 안에서 조금씩 달라, 캐시(건물 좌표)를 기준으로 삼았습니다.
- `geo_precision`: `site` 사이트가 준 좌표, `building` 도로명주소 건물 좌표, `place_search` 상호 검색으로 찾은 좌표. `geo_cache.json`에도 같은 값이 들어 있습니다.
- `places` 가운데 맛집과 ID가 같은 3,642행도 같은 좌표로 맞췄습니다. 맛집이 아닌 전시·행사 127건은 원본 좌표를 그대로 둡니다.

## 스키마

테이블: `themes` · `places` · `restaurants` · `restaurants_extra` · `programs` · `metadata`

`restaurants` 기본 34열은 벨루가·맛집도감 원본과 같고 끝에 5열이 붙습니다.

| 추가 컬럼 | 의미 |
|---|---|
| `source` | `velooga` / `lovizu` |
| `geo_provider` | 좌표 출처(Google Maps / food.lovizu.com) |
| `geo_precision` | `site` · `building` · `place_search` |
| `dup_group` | 같은 상호·같은 도로명주소 그룹 ID(`D0001`…), 없으면 NULL |
| `dup_count` | 그룹 행 수(1이면 고유) |

`themes`에는 `source`, `theme_group`이, `places`에는 `source`가 추가됩니다.

뷰 11종:

| 뷰 | 용도 |
|---|---|
| `v_jeju_restaurants` · `v_daegu_restaurants` | 기존 호환(제주 131 / 대구 83) |
| `v_restaurants_by_region` · `v_restaurants_by_theme` | 기존 호환 통계 |
| `v_restaurants_by_source` | 소스별 건수·좌표 보유 |
| `v_unified_full` | 맛집 + 러비즈 추가정보(평점·영업시간·링크) 조인 |
| `v_unified_dedup` | 중복 그룹당 1행(러비즈 행·좌표 있는 행 우선) = 3,434곳 |
| `v_restaurants_by_cuisine` · `v_lovizu_extra` | 기존 러비즈 뷰 호환 |
| `v_restaurants_by_theme_group` | 프로그램 이름으로 합친 테마 통계 |
| `v_restaurants_by_curated_theme` | `curated_theme_ids`를 펼친 테마 통계(지역 테마 포함) |

## SQL 예시

```sql
-- 제주 / 대구 (기존 뷰 그대로)
SELECT * FROM v_jeju_restaurants;
SELECT * FROM v_daegu_restaurants;

-- 소스 구분 없이 중복 제거한 목록에서 지역·음식으로 찾기
SELECT name, source, sido_short, sigungu, food_category, address, latitude, longitude
FROM v_unified_dedup WHERE sido_short='대구' AND food_category LIKE '%국밥%';

-- 평점·영업시간까지 (맛집도감 수록분)
SELECT name, sido_short, food_category, kakao_rating, naver_rating, business_hours, post_url
FROM v_unified_full WHERE kakao_rating >= 4.5 ORDER BY kakao_rating DESC LIMIT 20;

-- 지도용 좌표 (중복 제거)
SELECT id, name, latitude, longitude, geo_precision FROM v_unified_dedup
WHERE latitude IS NOT NULL;

-- 두 소스가 함께 소개한 가게
SELECT dup_group, group_concat(source || ':' || name, ' | ') FROM restaurants
WHERE dup_group IS NOT NULL GROUP BY dup_group HAVING count(DISTINCT source)=2 LIMIT 10;

-- 소스별 비중
SELECT * FROM v_restaurants_by_source;
```

## 주의

- **영업시간·가격·휴무는 바뀝니다.** 맛집도감 값은 사이트 표기 확인일(주로 2026-11-23) 기준이고, 벨루가 설명은 방송·수집 시점 기준입니다. `restaurants_extra.rating_checked_at`을 함께 보세요.
